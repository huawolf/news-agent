# News Agent - MCP Reporting and HTTP APIs

> Part of the [system architecture](system-architecture.md). Section numbers are preserved for code cross-references.

## 9. MCP Reporting

### 9.1 Transport and mounting

Reporting is MCP, not a custom REST endpoint. Master mounts a `FastMCP("news-agent-master")` Streamable HTTP app into the existing FastAPI process, so no extra port or process is required.

The in-app path is `/api/mcp`, derived from `report.path`. The SDK default `streamable_http_path` is `/mcp`. The mount point is `/api`; the external path after Caddy prefix stripping is `/news/api/mcp`.

| Requirement | Implementation | Reason |
|---|---|---|
| Mount point | `app.mount("/api", mcp.streamable_http_app())` | Mounting at `/api/mcp` makes Starlette 307-redirect `POST /api/mcp` to `/api/mcp/`; mounting at `/api` returns 200 directly. |
| Lifespan | Run `mcp.session_manager.run()` inside the parent FastAPI lifespan. | A mounted sub-app's lifespan does not run, so the session manager never starts and the handshake raises `ExceptionGroup`. |
| DNS rebinding protection | Configure `allowed_hosts` and `allowed_origins`; when both are empty, explicitly disable the SDK guard. | The SDK default allows only localhost, so a public Host behind Caddy is rejected with 421. |
| Auth placement | Wrap only `streamable_http_app()` in a pure ASGI wrapper. | Global FastAPI middleware would require JWT on anonymous portal routes; `BaseHTTPMiddleware` buffers SSE responses and conflicts with MCP. |

Slaver holds one long-lived `streamablehttp_client` context across fetch cycles and reuses the `Mcp-Session-Id`. Reinitialize only after a broken connection.

The SDK request body limit is 4 MiB. Exceeding it raises a transport exception, not a JSON-RPC error, so slaver cannot classify it as a business rejection. Truncate each `content` field to 8 KB before upload (`report.content_max_bytes`, default 8192). A 200-item batch then stays well below the limit.

### 9.2 Authentication

MCP requests use the same header as sync:

```text
Authorization: Bearer <manai-pic JWT>
```

Master validates the token during the handshake through manai-pic. Failure returns HTTP 401 with `{"error": "unauthorized"}` before tool dispatch. There is no default identity and no user field in the request body can override the verified identity.

The yield snapshot tool uses a separate shared key. `REPORTER_KEY` is configured on master and compared in constant time during the handshake. A successful key match marks the request as a reporter-key request and deliberately does not create an `Identity`. The tool also checks its `reporter_key` argument. A reporter-key credential cannot call user-identity tools.

The SDK's OAuth `token_verifier` is not used. This integration verifies a manai-pic bearer token directly and writes the verified `user_id` into the ASGI scope.

### 9.3 Tool: `report_signals`

The input is one flat array. Validation is per item so one invalid entry does not discard a whole batch.

```json
{
  "items": [
    {
      "url": "https://example.com/article",
      "batch_id": "20261002T083100.000000Z-example",
      "title": "Nvidia raises guidance",
      "content": "Nvidia raised its quarterly revenue guidance.",
      "summary": "Optional summary generated by slaver.",
      "source_name": "Reuters",
      "published_at": "2026-10-02T08:31:00Z",
      "assets": ["NVDA", "CRUDEOIL"],
      "direction": "bullish",
      "source_language": "en",
      "source_keywords": ["nvidia", "guidance"]
    }
  ]
}
```

| Field | Required | Limit | Meaning |
|---|---|---|---|
| `url` | No | 2048 | Normalized URL. Empty means no URL and BM25-only deduplication. The scoring layer uses an internal short key and restores the URL afterward. |
| `batch_id` | Yes | 64 | Local fetch-cycle identifier. Stored for synchronization and traceability; not an idempotency key or dedup input. |
| `title` | Yes | 512 | Collected title in the language declared by `source_language`. Translated before scoring when needed and stored in that locale's translation row. |
| `content` | Yes | 8192 characters | Source-language body fragment. Master rejects overlong values with `too_long: content`; it does not truncate. Slaver truncates by `report.content_max_bytes` before upload. |
| `summary` | No | 2048 | Optional slaver summary. Passed through in the main language; translated for the main table when the source language differs, with the original stored in the translation row. |
| `source_name` | Yes | 128 | Display name of the source. |
| `published_at` | No | - | ISO 8601. Not used for the sync window. |
| `assets` | No | 5 | Normalized uppercase English asset names. |
| `direction` | No | - | `bullish`, `bearish`, or `neutral`; invalid values become `neutral`. |
| `source_language` | No | - | Content language, currently `zh` or `en`. Omitted means main language for compatibility with older slavers. |
| `source_keywords` | No | 10 items, 64 chars each | Slaver-language keywords. Written only to that locale's `signal_translation`; never the main table. Overlong or excess values are normalized or shortened. |

Field mapping:

| MCP field | Source before upload |
|---|---|
| `url` | Optional collected URL. The scoring prompt uses a short per-batch key, then the application maps it back. A URL-less item is stored and reported with an empty URL. |
| `source_name` | Collector `source` such as RSS feed title or adapter name. Stored as `signal.source_name`. |
| `content` | Collector body or summary, truncated by the configured byte limit. |
| `assets`, `direction` | Scoring output after normalization and enum validation. |

The request shape must be `{"items": [...]}`. A signature such as `report_signals(payload: ReportRequest)` would make FastMCP generate `{"payload": {"items": [...]}}`. Use `report_signals(items: list[dict])` and validate each item inside the tool.

Unknown fields are ignored, not rejected. Master reads only `url`, `batch_id`, `title`, `content`, `summary`, `source_name`, `published_at`, `assets`, `direction`, `source_language`, and `source_keywords`. A request cannot inject `score`, `sectors`, main-table `keywords`, `origin`, or `reported_by`.

Reasons for the read-only whitelist:

- `score` is recomputed by master so one scoring policy governs the shared pool.
- `sectors` must come from master's current enabled sector list.
- Main-table `keywords` are generated by master from the main-language title and content. `source_keywords` are allowed only because they stay in the source-language translation row.
- `origin` and `reported_by` are derived from the verified JWT; accepting them from the body would allow forgery.

Example response:

```json
{
  "received": 200,
  "inserted": 150,
  "scored": 169,
  "hidden": 19,
  "duplicates": 29,
  "rejected": [
    {"index": 7, "url": "https://example.com/bad", "reason": "missing_required_field: content"},
    {"index": 199, "url": "https://example.com/over-quota", "reason": "quota_exceeded: daily scoring limit"}
  ],
  "energy_credited": 150,
  "quota": {
    "limit": 100,
    "used": 100,
    "remaining": 0,
    "date": "2026-11-13",
    "timezone": "Asia/Shanghai",
    "resets_at": "2026-11-13T16:00:00Z"
  },
  "server_time": "2026-10-02T09:00:00Z"
}
```

Invariants:

```text
received == inserted + hidden + duplicates + len(rejected)
scored == inserted + hidden
energy_credited == inserted
```

`rejected` carries the zero-based input `index` and the candidate URL. Reason prefixes are stable and machine-readable: `missing_required_field: <field>`, `invalid_field: <field>`, `too_long: <field>`, `invalid_url`, `untranslated: item`, and `quota_exceeded: daily scoring limit`.

`inserted` counts publicly visible new signals. `hidden` counts scored rows hidden by the visibility floor or a quality flag. `scored` is their sum. `energy_credited` equals `inserted`; a fully duplicate batch credits zero.

The daily quota is reserved after URL deduplication and before translation, BM25, and scoring. It is keyed by `(user_id, usage_date)` in `report.quota_timezone`, updated atomically, and persisted across requests and sessions. URL duplicates do not consume quota.

### 9.4 Tool: `get_server_info`

This is a connectivity and identity self-check tool. It performs no writes. The current slaver orchestrator does not call it during a fetch cycle.

It returns the verified `user_id`, server time, current enabled sector names, energy balance, and a quota object shaped like the one in `report_signals`. The sector list is diagnostic only; report bodies never send sectors.

### 9.5 Tool: `upsert_yield_pools`

This tool replaces the entire `yield_pool` snapshot. It never triggers scoring, deduplication, sector assignment, delivery, or signal storage. It uses `REPORTER_KEY`, not a manai-pic JWT.

```json
{
  "reporter_key": "<REPORTER_KEY>",
  "items": [
    {
      "pool_name": "PT-reUSD-10DEC2026",
      "url": "https://app.pendle.finance/trade/markets/0xabc/swap",
      "reference": "reUSD",
      "protocol": "Pendle V2",
      "chain": "Ethereum",
      "tvl_usd": 12622972,
      "apy_30d": 11.69658,
      "apy_today": 11.67504,
      "expiry_date": "2026-12-10"
    }
  ]
}
```

| Field | Required | Rules |
|---|---|---|
| `reporter_key` | Yes | Must match master `REPORTER_KEY`; constant-time comparison. |
| `pool_name` | Yes | At most 256 characters. |
| `url` | Yes | HTTP(S), at most 2048 characters. |
| `reference` | Yes | At most 128 characters. |
| `protocol` | Yes | At most 128 characters. |
| `chain` | Yes | At most 64 characters. |
| `tvl_usd` | Yes | Finite and greater than 0. |
| `apy_30d` | Yes | Finite percentage value. |
| `apy_today` | Yes | Finite percentage value. |
| `expiry_date` | Yes | ISO `YYYY-MM-DD`, `null`, or empty string. The key must exist. |

The entire batch is validated before any write. If any item is invalid, the batch is rejected, `deleted = 0`, `inserted = 0`, and the old snapshot remains. A valid batch deletes old rows and inserts the new snapshot in one transaction. An empty array is valid and clears the table.

`reporter` and `recorded_at` are written by the server; request values are ignored. Unknown fields are ignored.

```json
{
  "received": 34,
  "deleted": 30,
  "inserted": 34,
  "replaced": true,
  "rejected": []
}
```

`replaced = false` means the batch was rejected and the old snapshot is intact.

### 9.6 Batching, idempotency, and failures

- `report.batch_size` defaults to 200. Over-limit requests return an MCP `InvalidRequest`; master never silently truncates.
- The SDK 4 MiB body limit is handled by slaver-side content truncation. Raising the limit is not the primary control.
- A batch with a URL relies on URL then BM25 deduplication for idempotency. A URL-less item relies only on the BM25 high threshold, so exact idempotency is not guaranteed in the gray band.
- Incremental sync uses the master signal id as the stable local identity for URL-less items and for late-translation association.
- `batch_id` identifies a real fetch cycle across local storage, reporting, and sync. It is not a request or chunk id, idempotency key, or dedup input.
- Transport failures retry `report.retry_attempts` times (default 3) with exponential backoff from `report.retry_backoff_seconds` (default 1.0). Authentication failures do not retry. Business rejections do not retry.
- `report_signals` commits per item. One invalid item enters `rejected` while valid items persist.
- `upsert_yield_pools` is atomic: one invalid item rejects the whole snapshot.

| Failure class | Symptom | Slaver behavior |
|---|---|---|
| Authentication | HTTP 401 with `{"error": "unauthorized"}` | Fail the batch, trigger login, do not retry. |
| Protocol or transport | JSON-RPC error, `ExceptionGroup`, or 4 MiB exception | Retry with backoff. URL items are protected by URL/BM25; URL-less items have only the BM25 high threshold. |
| Business rejection | Item in `rejected` | Do not retry. Mark only that item failed; the rest of the batch succeeded. |

### 9.7 Master report pipeline

```text
1.  Validate JWT during MCP handshake; failure returns 401 with no default identity
2.  Check item count; over report.batch_size returns InvalidRequest without truncation
3.  Validate each item; missing, overlong, or invalid-URL items enter rejected
4.  Normalize assets, validate direction, validate source_language
5.  URL deduplication when a URL exists
6.  Reserve the reporter's daily scoring quota; over-limit items enter rejected
7.  Translate title and summary to the main language when source_language differs; failure rejects the item
8.  BM25 deduplication for all remaining items; high-threshold matches archive only
9.  Batch-score non-duplicates for main-language score, sectors, assets, direction, title, summary, and keywords
10. Split visible and hidden rows; score < 60 or any quality flag writes a hidden row
11. Persist with origin = slaver:<user_id> and reported_by = <user_id>; write translations as specified in 6.3
12. Credit +1 for each visible new signal; hidden rows receive no energy and no translation
```

## 10. HTTP APIs

### 10.1 Master anonymous APIs

| Method | Path | Behavior |
|---|---|---|
| `GET` | `/api/server/signals` | Latest seven days only. No time-window parameter. Supports `group=all\|hot\|watchlist`, `sector`, `regions`, `q`, `direction`, `asset`, `min_score` (strict `final_score` comparison), `locale`, and `page`. Sort order is `batch_id DESC, final_score DESC, first_seen_at DESC, id DESC`. |
| `GET` | `/api/server/signals/{id}` | One signal detail. |
| `GET` | `/api/server/reporters/{user_id}` | Public reporter profile and statistics. Rate fields return `null` with fewer than ten samples; `user_id = 0` returns 404. |
| `GET` | `/api/server/reporters/{user_id}/signals` | Complete public reporter history. Supports sector, text, direction, region, asset, optional `min_score`, locale, and pagination. No seven-day window; still requires `score >= 60`. |
| `GET` | `/api/server/watchlist-assets` | Watched assets and seven-day hit counts under the current filters. Zero-count rows included. |
| `GET` | `/api/server/sectors` | Enabled sectors and keyword hints for portal filters. |
| `GET` | `/api/server/github-trending` | Rolling seven-day GitHub cache with `score`, `summary`, `name`, and `first_seen_at`. `locale` overlays completed translations. |
| `GET` | `/api/server/sources` | Shared source catalogue used by slaver for overlap detection. |
| `GET` | `/api/server/yields` | Current yield snapshot, sorted by Today APY descending. Supports exact `protocol` and `chain` filters. |
| `GET` | `/api/server/latest-digest` | Latest compiled digest. `locale` selects the language; defaults to the main locale. |

Anonymous APIs are for portal rendering only. They never expose incremental sync, and they never return email, phone, or other account fields. Every signal read returns visible rows only.

All `/api/me*` endpoints use the verified JWT. On master, `/api/console/*`, `/api/sources*`, and `/api/backoffice/*` require an admin identity.

### 10.3 Master MCP

| External path | Path after stripping | Behavior |
|---|---|---|
| `/news/api/mcp` | `/api/mcp` | MCP Streamable HTTP; Bearer JWT or `REPORTER_KEY` depending on the tool. |

Tools are `report_signals`, `get_server_info`, and `upsert_yield_pools`. There is no REST shadow endpoint such as `POST /api/report/signals`.

### 10.4 Slaver local APIs

The slaver serves a local portal and a loopback-only console. Sync and reporting are outbound only; there is no local inbound sync or report API. Browsing is anonymous. Console access does not require manai-pic login.

| Method | Path | Behavior |
|---|---|---|
| `GET` | `/api/status` | Health check returning `{"status": "running", "mode": "slaver"}`. Master does not expose this route. |
| `GET` | `/api/server/signals`, `/api/server/watchlist-assets`, `/api/server/sectors`, `/api/server/github-trending`, `/api/server/yields` | Local read-only portal data with master-compatible response contracts. |
| `GET` | `/api/server/reporters/{user_id}`, `/api/server/reporters/{user_id}/signals` | Shared reporter routes for locally stored shared signals. |
| `GET` | `/api/signals` | Compatibility list of the last 24 hours with `page`, `page_size`, and `locale`. |
| `GET` | `/api/auth/status` | Revalidate the stored JWT and return verified display information, never the token. |
| `GET` | `/api/auth/login`, `/api/manai/auth/callback` | Start local login and handle the manai-pic callback. |
| `PUT`, `DELETE` | `/api/auth/token` | Verify and save a token, or clear it. |
| `GET`, `PUT` | `/api/me/preferences` | Read or save the signed-in user's regions and signal settings. Loopback console only. |
| `GET`, `PUT`, `POST` | `/api/me/watchlist` | Read, replace, or add assets recognized from free text. POST returns the full list and recognized tickers; missing LLM configuration returns 400; no recognized asset returns 422. |
| `GET`, `POST` | `/api/sources` | List or add RSS sources. |
| `GET` | `/api/sources/feed` | Read-only Feed catalogue. |
| `PUT`, `DELETE` | `/api/sources/{kind}/{key}` | Update or delete an RSS source. |
| `GET`, `PUT`, `POST` | `/api/console/llm`, `/api/console/llm/test`, `/api/console/feishu`, `/api/console/feishu/test`, `/api/console/telegram`, `/api/console/telegram/test`, `/api/console/telegram/bind` | Local LLM and delivery configuration and tests. |
| `GET`, `PUT` | `/api/console/preferences` | Read or save local natural-language ranking preferences. |
| `GET`, `PUT` | `/api/console/delivery` | Read or save local fetch and push scheduling. |
| `GET` | `/api/console/fetch-status` | Poll fetch progress. |
| `POST` | `/api/console/fetch-once` | Run the full slaver orchestration pipeline under the scheduler lock. |

Local console APIs accept loopback clients only and reject common forwarded headers. Local browsing does not require login. A standalone slaver (`server_url` empty) does not require manai-pic; login is needed only to connect to a master.
